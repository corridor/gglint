<RuleSpec command="gglint secrets" severity="problem; warning if gitignored" fix="env var, where the agent reads one" />

A password or key with no recognisable format, which gglint finds by where it's written: under a
name like `token`, `password` or `Authorization`; inside a URL such as
`postgresql://admin:…@db/app`; or in a command an agent saved after you approved it, such as
`PGPASSWORD=… psql` or `curl -H "Authorization: Bearer …"`. Scanners that only look for token
formats miss all of these.

```json
// .claude/settings.local.json
{ "permissions": { "allow": ["Bash(PGPASSWORD=… psql -h db -U app)"] } }
```

```text
./.claude/settings.local.json:1:47  inline-credential credential in "PGPASSWORD" is written out in the file
```

## Fixing it

If the secret is under a name, `uvx gglint secrets --fix` replaces it with an environment
variable. If it's in a URL, read the URL from an environment variable instead. If it's in a
saved command, remove the command (`/permissions` in Claude Code) and pass the secret from your
environment. Either way, rotate anything that was committed.

To keep false alarms down, gglint skips references like `${DB_PASSWORD}`, passwords shorter than
8 characters or made of one kind of letter, and passwords in commands with no digit or symbol.
