title: Check before every commit
description: Run gglint secrets on staged files before each commit, through husky, git hooks, pre-commit, lefthook or lint-staged.
---

`gglint hook` runs `gglint secrets --staged` before each commit, so a secret never gets
committed in the first place. From the root of a repository:

```sh
uvx gglint hook
```

It uses the hook tool your repository already has:

| Tool        | What `gglint hook` does                                                |
| ----------- | ---------------------------------------------------------------------- |
| husky       | Adds the command to `.husky/pre-commit`, keeping what's there.         |
| git         | Adds it to git's `pre-commit` hook, wherever `core.hooksPath` puts it. |
| pre-commit  | Prints the lines for `.pre-commit-config.yaml`.                        |
| lefthook    | Prints the lines for `lefthook.yml`.                                   |
| lint-staged | Prints the lines for `package.json`.                                   |

Running it twice changes nothing, and an existing hook script is extended once, never
overwritten.

## Options

| Option         | Effect                                                     |
| -------------- | ---------------------------------------------------------- |
| `--tool NAME`  | Use this tool instead of detecting one.                    |
| `--with-mcp`   | Also check that every agent gets the same MCP servers.     |
| `hook print`   | Print the lines to add, and change nothing.                |
| `PATH`         | The repository's root. Defaults to the current directory.  |

## In a JavaScript repository

In a repository with a `package.json`, `gglint hook` first adds `@gglint/cli`, pinned to its
version, to the dev dependencies with the repository's package manager: npm, pnpm, yarn or bun,
from the `packageManager` field or the lockfile. The hook then runs that copy, so everyone who
installs the repository's packages has it, and nobody needs uv:

| Package manager | Added with                                          | The hook runs        |
| --------------- | --------------------------------------------------- | -------------------- |
| npm             | `npm install --save-dev --save-exact @gglint/cli`   | `npx --no -- gglint` |
| pnpm            | `pnpm add --save-dev --save-exact @gglint/cli`      | `pnpm exec gglint`   |
| yarn            | `yarn add --dev --exact @gglint/cli`                | `yarn gglint`        |
| bun             | `bun add --dev --exact @gglint/cli`                 | `bun run gglint`     |

None of these downloads a gglint the repository doesn't list. If the package manager fails, the
hook isn't written, since it would stop every commit; `gglint hook print` shows the command to
run first.

In any other repository, the hooks run `uvx gglint@<version>`, pinned to the version that
wrote them, so everyone who commits needs [uv](https://docs.astral.sh/uv/) installed.

## With the pre-commit framework

gglint is also a source of hooks for [pre-commit](https://pre-commit.com):

<Tabs>
  <TabItem label="Secrets only">
    ```yaml
    # .pre-commit-config.yaml
    repos:
      - repo: https://github.com/corridor/gglint
        rev: v0.5.0
        hooks:
          - id: gglint-secrets
    ```
  </TabItem>
  <TabItem label="Secrets and MCP">
    ```yaml
    # .pre-commit-config.yaml
    repos:
      - repo: https://github.com/corridor/gglint
        rev: v0.5.0
        hooks:
          - id: gglint-secrets
          - id: gglint-mcp
    ```
  </TabItem>
</Tabs>

`gglint-secrets` runs on the agent files staged in each commit. `gglint-mcp` runs when an MCP
config file changes, and checks the whole repository.
